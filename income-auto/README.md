# income-auto

글쓰기 자산(`../writing/`)을 **수익**으로 바꾸는 저장소. 목적이 다른 두 트랙을 한 폴더에서 굴린다.

| 트랙 | 목표 | 회수 시점 | 성공 기준 |
|---|---|---|---|
| 1. `kmong/` | 크몽 전자책 판매 | 이번 달 현금 | 등록 승인 + 첫 결제 3건 |
| 2. `blog-auto/` | 검색 유입 블로그 자산 | 6개월 | 월 방문 1,000 / 애드센스 승인 |

두 트랙은 **같은 원고를 공유한다.** 전자책 한 챕터를 잘라 블로그 글로 내보내고,
블로그에서 반응이 온 주제를 전자책 개정판에 되먹인다. 그래서 한 폴더에 둔다.

## 디렉터리

```
income-auto/
├── kmong/
│   ├── 01_체크리스트.md      등록 D-14 ~ 발행 후 운영까지 실행 순서
│   ├── 02_서비스문안.md      크몽 상세페이지에 그대로 붙여넣을 문안
│   └── 03_전자책원고.md      판매할 전자책 원고 (목차 + 본문 골격)
│
└── blog-auto/
    ├── keywords.csv          발행 대기 키워드 큐 (헤더만 있는 빈 큐)
    ├── drafts/               초안 (자동 생성, status: draft)
    ├── approved/             검수 통과분 (사람이 TODO 채운 뒤 이동)
    ├── published/            발행 완료분 + 발행 URL 기록
    └── logs/                 발행/유입 로그
```

## 2트랙 흐름

```
keywords.csv 큐  →  drafts/ 초안 생성  →  사람이 TODO 채움  →  approved/  →  발행  →  published/ + logs/
```

`keywords.csv` 컬럼 (헤더만 있는 빈 큐 상태로 시작한다):

| 컬럼 | 값 | 설명 |
|---|---|---|
| `keyword` | 문자열 | 노릴 검색어 그대로 |
| `search_intent` | `정보` / `비교` / `실행` | 검색한 사람이 원하는 것 |
| `priority` | 1~3 | 1이 먼저 |
| `target_url_slug` | 영문 슬러그 | 발행 URL 조각 |
| `status` | `queued` / `draft` / `approved` / `published` | 현재 위치 |
| `drafted_at` | YYYY-MM-DD | 초안 생성일 |
| `published_at` | YYYY-MM-DD | 발행일 |
| `note` | 자유 | 경쟁 문서 수, 참고 링크 등 |

키워드는 **1트랙 전자책 목차에서 뽑는다.** 한 챕터 = 한 글이 기본이고,
반응이 온 글은 전자책 개정판에 되먹인다.

## 운영 규칙

### 1. 사실은 지어내지 않는다

`../writing/STYLE.md` 의 1번 규칙을 여기서도 그대로 지킨다.
**돈을 받는 글이므로 더 엄격하게 적용한다.**

- 실제 사업명, 발주처명, 고객사 담당자 발언, 장애 사례, 금액은 `<!-- TODO: 실제 사례 -->` 로 비운다.
- 크몽 수수료율·정산 주기처럼 플랫폼이 바꿀 수 있는 숫자는 **출처 링크와 확인 날짜**를 같이 적는다.
- 자동 생성물은 전부 `status: draft` 로 시작한다. 사람이 채우고 `ready` 로 바꿔야 판매·발행 대상이 된다.

### 2. 비밀유지 (NDA) 경계선

공공 IT 사업 경험을 파는 상품이다. 다음은 원고에 **절대 넣지 않는다.**

- 발주처 실명 + 구체 사업명 조합, 사업 금액, 계약 조건
- 실제 산출물 파일 원본, 내부 시스템 화면, 구성도, IP·계정 정보
- 특정 인물이 식별되는 일화

넣어도 되는 것: **일반화한 절차, 구조, 판단 기준, 공개된 법령·지침**.
판단이 애매하면 넣지 않는다. 상품 하나보다 경력이 비싸다.
