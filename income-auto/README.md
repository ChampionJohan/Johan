# income-auto

글쓰기 자산(`../writing/`)을 **수익**으로 바꾸는 저장소. 목적이 다른 두 트랙을 한 폴더에서 굴린다.

**목표: 월 50만원 (실수령).** 달성 시점은 3개월차로 잡는다. 근거와 산수는 `00_실행계획.md`.

| 트랙 | 목표 | 회수 시점 | 성공 기준 |
|---|---|---|---|
| 1. `kmong/` | 첨삭·상담 서비스 + 전자책 | 이번 달 현금 | 1개월차 리뷰 3건 → 3개월차 월 50만원 |
| 2. `blog-auto/` | 크몽으로 보내는 검색 유입 | 6개월 | 월 방문 5,000 / 크몽 유입 5건 |

블로그의 목표는 광고 수익이 아니라 **크몽 유입**이다. 같은 방문자로 광고는 1만원,
상품 유입은 30만원이 된다 (`00_실행계획.md` 6절). 그래서 광고보다 상품 링크를 먼저 붙인다.

두 트랙은 **같은 원고를 공유한다.** 전자책 한 챕터를 잘라 블로그 글로 내보내고,
블로그에서 반응이 온 주제를 전자책 개정판에 되먹인다. 그래서 한 폴더에 둔다.

## 디렉터리

```
income-auto/
├── 00_실행계획.md            ← 먼저 읽는다. 월 50만원의 산수와 4주 일정
├── 01_크몽_따라하기.md      가입 다음의 7단계. 클릭 순서대로
│
├── tools/md2html.py          md → html 변환 (저장소 tools/mdlite.py 재사용, 의존성 없음)
├── html/                     변환 결과. 휴대폰으로 열거나 인쇄해서 보는 용도
│
├── kmong/
│   ├── 01_체크리스트.md      등록 D-14 ~ 발행 후 운영까지 실행 순서
│   ├── 02_서비스문안.md      전자책 상세페이지 문안
│   ├── 03_전자책원고.md      전자책 원고 (목차 + 본문 골격)
│   └── 04_첨삭서비스문안.md  첨삭·상담 상품 문안 ← 원고 없이 오늘 등록 가능
│
└── blog-auto/
    ├── keywords.csv          발행 대기 키워드 큐 (헤더만 있는 빈 큐)
    ├── drafts/               초안 (자동 생성, status: draft)
    ├── approved/             검수 통과분 (사람이 TODO 채운 뒤 이동)
    ├── published/            발행 완료분 + 발행 URL 기록
    └── logs/                 발행/유입 로그
```

## 2트랙 플랫폼: 티스토리 (확정)

비용 0원, 애드센스 직접 게재 가능, 다음+구글 양쪽 유입, 공식 API 종료로 자동화는
Playwright 브라우저 조작뿐 — 기술 선호와도 맞는다. 선택 근거와 탈락 사유는 `00_실행계획.md` 5절.

## 2트랙 흐름

```
keywords.csv 큐  →  drafts/ 초안 생성  →  사람이 TODO 채움  →  approved/  →  발행  →  published/ + logs/
```

`keywords.csv` 컬럼 (헤더만 있는 빈 큐 상태로 시작한다):

| 컬럼 | 값 | 설명 |
|---|---|---|
| `keyword` | 문자열 | 노릴 검색어 그대로 |
| `search_intent` | `정보` / `비교` / `실행` | 검색한 사람이 원하는 것 |
| `priority` | 1~3 | 1이 먼저 |
| `target_url_slug` | 영문 슬러그 | 발행 URL 조각 |
| `status` | `queued` / `draft` / `approved` / `published` | 현재 위치 |
| `drafted_at` | YYYY-MM-DD | 초안 생성일 |
| `published_at` | YYYY-MM-DD | 발행일 |
| `note` | 자유 | 경쟁 문서 수, 참고 링크 등 |

키워드는 **1트랙 전자책 목차에서 뽑는다.** 한 챕터 = 한 글이 기본이고,
반응이 온 글은 전자책 개정판에 되먹인다.

## 읽는 순서

1. `00_실행계획.md` — 왜 이 순서인가, 얼마가 들어오는가
2. `01_크몽_따라하기.md` — 지금 무엇을 클릭하는가
3. `kmong/04_첨삭서비스문안.md` — 등록 화면에 붙여넣을 문안

휴대폰으로 보거나 인쇄하려면 HTML 판을 만든다. 체크박스를 눌러 표시할 수 있다.

```
python3 income-auto/tools/md2html.py              # 전체 변환
python3 income-auto/tools/md2html.py 01_크몽_따라하기.md
```

## 운영 규칙

### 1. 사실은 지어내지 않는다

`../writing/STYLE.md` 의 1번 규칙을 여기서도 그대로 지킨다.
**돈을 받는 글이므로 더 엄격하게 적용한다.**

- 실제 사업명, 발주처명, 고객사 담당자 발언, 장애 사례, 금액은 `<!-- TODO: 실제 사례 -->` 로 비운다.
- 크몽 수수료율·정산 주기처럼 플랫폼이 바꿀 수 있는 숫자는 **출처 링크와 확인 날짜**를 같이 적는다.
- 자동 생성물은 전부 `status: draft` 로 시작한다. 사람이 채우고 `ready` 로 바꿔야 판매·발행 대상이 된다.

### 2. 비밀유지 (NDA) 경계선

공공 IT 사업 경험을 파는 상품이다. 다음은 원고에 **절대 넣지 않는다.**

- 발주처 실명 + 구체 사업명 조합, 사업 금액, 계약 조건
- 실제 산출물 파일 원본, 내부 시스템 화면, 구성도, IP·계정 정보
- 특정 인물이 식별되는 일화

넣어도 되는 것: **일반화한 절차, 구조, 판단 기준, 공개된 법령·지침**.
판단이 애매하면 넣지 않는다. 상품 하나보다 경력이 비싸다.

### 3. 겸직 확인이 먼저다

재직 중 부수입 활동이다. **회사 취업규칙의 겸직 조항을 확인하기 전에는 아무것도 등록하지 않는다.**
또한 회사가 참여하는 시장과 겹치는 상품(입찰 제안서 첨삭, 산출물 대행)은 만들지 않는다.
이유와 허용 범위는 `00_실행계획.md` 3절.

### 4. 진행 현황

- [ ] 0. 회사 취업규칙 겸직 조항 확인 ← **모든 것의 선행 조건**
- [ ] 1트랙: 첨삭 서비스(A) 등록 ← 1주차, 원고 불필요
- [ ] 1트랙: 상담 서비스(B) 등록 ← 1주차
- [ ] 1트랙: 리뷰 3건 확보 ← 2주차, 첫 달의 진짜 목표
- [ ] 1트랙: 전자책 원고 TODO 채우고 등록 ← 3주차
- [ ] 2트랙: 티스토리 개설 + 검색엔진 등록 ← 4주차
- [ ] 2트랙: `keywords.csv` 에 키워드 30개 채우기
- [ ] 2트랙: 주 2회 발행 루틴 정착
