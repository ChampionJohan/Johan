## 3. 상세 설명 (본문)

> 아래 블록 전체를 상세페이지에 붙여넣는다. 앞 3줄이 구매를 결정한다.

### 이런 상황이라면

- 공공 IT 사업에 처음 투입됐는데, 무슨 문서를 언제 내야 하는지 아무도 알려주지 않는다
- 착수계, 수행계획서, 주간보고, 검사원까지 이름은 들어봤지만 순서와 관계를 모르겠다
- 발주처 보고 때마다 되묻는 질문이 반복된다
- 앞사람이 쓰던 양식을 물려받았지만, 왜 그렇게 쓰는지는 모른 채 채우고 있다

### 무엇을 담았나

공공 IT 구축·운영 사업의 **전 주기 업무 순서와 산출물 구조**를 한 권으로 정리했습니다.
이론서가 아니라, 내일 아침 회의에서 쓰는 순서대로 배열했습니다.

1. 사업 단계 지도 - 착수 / 수행 / 검사 / 인수 단계별로 무엇이 오가는가
2. 단계별 산출물 목록과 작성 시점, 그리고 각 문서가 존재하는 이유
3. 주간·월간 보고 구조 - 발주처가 되묻지 않는 보고서의 공통점
4. 이슈와 리스크를 구분해 관리하는 법
5. 변경 요청이 들어왔을 때의 처리 순서
6. 검사·인수 단계에서 미리 준비해야 할 것들
7. 인수인계와 사업 종료 처리

### 부록 (템플릿)

바로 쓰는 빈 양식입니다. 특정 기관·사업의 실제 문서가 아닌, 새로 작성한 범용 양식입니다.

- 주간보고 양식
- 이슈·리스크 관리대장
- 단계별 산출물 체크리스트
- 회의록 양식

### 이런 분께 권합니다

- 공공 IT 사업에 처음 투입된 협력사 PM / 사업관리 담당자
- 개발·운영 인력이었다가 관리 역할을 맡게 된 분
- 공공 분야 진입을 준비하는 중소 IT 기업 실무자

### 이런 분께는 권하지 않습니다

- 이미 공공 사업 3건 이상을 관리해 본 분 (새로 얻을 내용이 적습니다)
- 특정 기관의 개별 지침·양식을 그대로 받길 원하는 분 (기관별 양식은 담지 않았습니다)

## 4. 패키지 구성

| 항목 | STANDARD | DELUXE | PREMIUM |
|---|---|---|---|
| 이름 | 본편 | 본편 + 템플릿 | 본편 + 템플릿 + 1:1 질의응답 |
| 전자책 본편 (PDF) | O | O | O |
| 부록 템플릿 4종 | - | O | O |
| 산출물 체크리스트 | - | O | O |
| 1:1 질의응답 (텍스트, 2주) | - | - | O |
| 가격 | <!-- TODO --> | <!-- TODO --> | <!-- TODO --> |
| 작업일 | 즉시 발송 | 즉시 발송 | 즉시 발송 + 2주 응대 |
| 수정 횟수 | - | - | - |

설계 원칙 세 가지.

1. **DELUXE를 팔기 위한 구조다.** STANDARD는 비교 기준, PREMIUM은 상한선 역할을 한다.
2. PREMIUM에만 시간이 드는 항목(질의응답)을 넣는다. 나머지는 복제 비용이 0이다.
3. 가격은 정가가 아니라 **수수료 차감 후 실수령액**으로 역산한다 (`01_체크리스트.md` A단계).

## 5. FAQ (5개)

**Q. 특정 기관의 공식 양식이 들어있나요?**
A. 아닙니다. 기관·사업별 양식은 발주처 지침을 따라야 합니다. 이 책은 어느 기관에서든 공통으로 적용되는 **문서의 순서와 구조**를 다룹니다. 부록 템플릿도 실제 사업 문서가 아닌 범용 빈 양식입니다.

**Q. 개발자인데 도움이 될까요?**
A. 관리 역할을 맡게 되었거나 맡을 예정이라면 도움이 됩니다. 개발 기술은 다루지 않습니다.

**Q. 환불이 되나요?**
A. 디지털 콘텐츠 특성상 파일 발송 후에는 환불이 제한됩니다. 상세 기준은 아래 취소·환불 규정을 확인해 주세요.

**Q. PREMIUM 질의응답은 어떻게 진행되나요?**
A. 구매일로부터 2주간 크몽 메시지로 진행합니다. 특정 사업의 계약·법률 판단이나 실제 산출물 대행은 포함되지 않습니다.
